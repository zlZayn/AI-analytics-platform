# 决策：文档引用指向整个文档，锚点校验对齐 GitHub（2026-09-11）

已实施。

## 问题

- 5 个 `src/**/__tests__/README.md` 逐字重复「全量 `npm test`，约定与 CI 见 docs/verification.md」，违反「同一事实只有一个 home」。
- 文档间存在「第 5 节」「文档网节」这类文字指针，不可点击、不可校验。
- `scripts/check-links.py --fragments` 的锚点算法与 GitHub 相反（下划线、标点处理），启用后会误报；且该开关在本项目空转（297 条链接中含 `#` 的为 0 条）。

## 决策

- 跨文档引用写成 `[名](路径.md)` 指向整个文档；不写由标题自动生成的小节锚点；确需文内定位时用显式 `<a id="...">`。
- 锚点算法对齐 github-slugger：保留下划线、标点删除而非替换、空格逐个转短横、同名标题补 `-1`/`-2`、围栏代码块内的 `#` 不算标题、显式 `a id` 视为有效锚点。
- 新增 `--refs`：行内出现 `.md` 却未做成链接即提示。**不设词表**（反引号内也算）；已成链的、围栏代码块内的、解析不到真实文件的、链回自己的不报。
- `--fragments` / `--refs` 均为警告级，不影响退出码；已写入三连校验与 CI。
- 脚本以 skill 版（`maintenance-flow/check-links.py`）为源头，项目 `scripts/` 为副本；改动必须回写 skill 后再覆盖。

## 替代方案

- **把文字指针改成小节锚点链接**：中文锚点可读性差、易写错，且标题一改就断链，故不采用。
- **保留脚本现状、只加校验开关**：会产出与 GitHub 相反的结论，属负资产。
- **让 warnings 计入退出码（阻断合并）**：会把「提示」升级为「拦截」，需单独决策与授权，本次不做。
- **给测试 README 建统一骨架模板**（含跨目录深度的相对路径规则）：收益低于其引入的复杂度，暂不做。
- **`--refs` 只在含指代动词（见/参见/详见/参阅/see）的行上判定**：误报更少，但词表是硬编码、行为不透明；改为「一律提示，真假交由读者判断」。
- **`--refs` 只报「能唯一确定目标」的写法**（带目录，或全库唯一同名）：本项目 0 误报，但会漏掉裸文件名引用；选择不静默，宁可多提示。

## 影响

- 链接不随标题改名断裂；`check-links.py` 可作 GitHub 锚点的可信依据。
- 项目副本与 skill 版须保持一致，分叉会导致两侧结论不同。
- `--fragments` 行为变化：代码块内的 `#` 不再被当作锚点（此前会漏报）。
