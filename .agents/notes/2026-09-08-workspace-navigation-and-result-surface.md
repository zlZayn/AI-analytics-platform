# 决策：跨页工作台入口与结果区状态边界（2026-09-08）

已实施/已否决：已实施

## 问题

探索页和查询历史页跳转到工作台后，URL 可能正常但 SQL 填充/自动执行依赖首帧 effect 顺序；结果区在无结果状态下直接返回孤立块，造成空白、重复边框和恢复路径不清晰。

## 决策

- `workspace-navigation.ts` 统一规范化 SQL 换行、生成 URL，并提供 `connection + SQL` 一次性应用 key。
- `SessionWorkspace` 以导航 key 驱动 SQL 草稿填充和 `SET_COMPILED_SQL`，兼容客户端导航期间参数晚到且不覆盖用户编辑。
- `SessionView` 保持固定结果容器，统一承载等待、执行中、成功、失败、洞察、探索和明细状态；成功结果由外层容器统一负责边框。
- 离线 E2E 覆盖探索页和历史页入口，分别断言 URL SQL、编辑器内容和单次 `/api/query`。

## 替代方案

- 继续依赖挂载时空依赖数组：无法处理客户端导航参数晚到，且 Strict Mode 下容易回归。
- 在探索页和历史页分别维护填充逻辑：入口契约继续分叉，编码和空值行为难以一致验证。
- 仅修 CSS 或增加结果占位：不能保证 SQL 已经进入执行管线，无法解决入口核心故障。

## 影响

入口参数、执行触发和结果状态各有单一职责；导航与结果区行为可通过纯函数单测和离线 E2E 回归，后续页面只需复用统一 URL 构造函数。
