# 决策：R 分析工作台重做（右侧停靠面板）（2026-09-11）

已实施

## 问题

- R 面板原先**内嵌在结果区 flex 流里**（`SessionView` 的 Tabs 之下）：一打开就抢走高度，结果区被压扁。
- 面板内部高度"各写各的"：内容块是 `space-y-2` 块流（编辑器的 `flex-1` 在块流里无效），输出写死 `max-h-[280px]`，而结果区又是 `overflow-hidden` → 编辑器被挤成细长条、内容被裁切，观感就是"全部挤在一起、超级错位"。
- 四处不同的水平内边距（header `px-3`、toolbar `px-1`、内容 `p-2`、状态栏 `px-3`），"数据注入中…"再占一行 → 密集且跳行。
- `if (!open) return null`：关闭即卸载，用户改过的 R 代码与输出全丢。

## 决策

- **呈现**：右侧停靠面板（`fixed inset-y-0 right-0 z-[60]`，宽 620px / 窄屏全宽，平移进出）→ 结果区布局零影响。
- **纵向契约**：头部 → 工具栏 → 内容（代码 + 分割条 + 输出）→ 状态栏；每段 `shrink-0`，滚动只发生在代码/输出内部，两者都有最小高度；极端视口下内容区自身滚动而不是裁切。
- **代码/输出可拖拽分割**：`role="separator"` + 指针拖拽 + ↑↓/Home 键盘操作，比例写 `localStorage`（默认 62%，夹 35%..80%）。
- **关闭保留状态**：首次打开后保持挂载（挂载时机由 `SessionView` 的 `rWorkbenchPinned` 在事件处理器里决定，不在 effect 里 setState——后者会被 lint 规则拦下且易级联渲染），关闭后 `aria-hidden + inert`。
- **模板先于运行时**：打开即写入 R 模板，初始化失败也能读/改/复制代码。
- 统一水平节奏：全部 `px-3`（内容 `p-3`），注入进度并入状态栏，不再额外跳行。

## 替代方案

- 结果区与 R 面板上下分栏 + 拖拽分隔：仍在同一块高度里争空间，窄屏必然二选一，且要多一层布局状态。
- R 作为第四个 Tab（图表/数据表/R）：`2026-09-03` 已否决——R 是手段不是交互主体。
- 面板打开时预留主内容宽度（`lg:pr-[620px]`）：1440px 下结果区被压到 ~340px，重新引入"挤"。
- 关闭即卸载：简单，但丢用户的代码与输出。

## 影响

- 打开 R 不再影响结果区；代码与输出各占其位、各自滚动，比例按用户习惯记忆。
- 离线或初始化失败时仍能取得 R 代码；关闭重开不丢状态。
- 新增测试：`clampSplitRatio` 边界与非法输入；离线 E2E 增加"关闭面板后 `aria-hidden` 且不再拦截结果区交互"的回归断言。
