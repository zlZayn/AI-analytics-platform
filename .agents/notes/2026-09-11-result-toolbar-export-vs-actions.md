# 决策：结果工具条分层（导出 = 带走，R 分析 = 就地分析）（2026-09-11）

已实施；部分取代 [2026-09-03 结果区三层视图化](2026-09-03-result-area-three-layer-tabs.md) 的「R 工作台入口移入导出菜单」

## 问题

- 「导出 ▼」菜单里同时有 导出 CSV / 导出 JSON / 复制 R 模板 / **R 分析**：前三项是"把数据或代码带走"，第四项是"在当前页面开一个分析环境"——类别不同，用户点「导出」找不到它，想分析也不会先点导出。
- 同一份 R 能力还分成「复制 R 模板」（外部 RStudio）与「R 分析」（浏览器内 WebR）两处，入口分散且没有并列说明。

## 决策

- **R 分析 = 结果区头部一级按钮**（outline，title 说明"当前结果注入 df，可写 dplyr/ggplot2"），与「导出 ▼」并列。
- **导出菜单只留三项**：导出 CSV / 导出 JSON / 复制 R 模板，每项加一行说明（Excel BOM / 完整结果集 / 粘贴到 RStudio），菜单宽 240px。
- 菜单 aria-label 由「导出与高级操作」改为「导出数据与代码」，与新层级一致。

## 替代方案

- 保持现状（R 分析留在导出菜单）：分类错误、发现性差，维护者已明确反馈"很奇怪"。
- 「复制 R 模板」也提到一级：头部回到"一行挤 4 个 10px 按钮"的拥挤态（2026-09-03 的问题）；模板本质是"带走代码"，留在导出里自洽。
- 新增工具条或独立 Tab 承载 R：`2026-09-03` 已否决——R 是手段不是交互主体。

## 影响

- 结果头部条：`分析结果` + 状态 + `R 分析` + `导出 ▼` +（已手动调整徽标）。
- 离线 E2E 的 R 入口改为直接点一级按钮。
